출발점이 다르다 — 먼저 지금 코드와 v4의 차이를 보고, 바뀐 것만 고친다.

## 순서: 기반 → 공용 컴포넌트 → 화면

공용 컴포넌트를 바꾸면 **아직 개편하지 않은 화면도 함께 바뀐다**(`Button` 하나에
7개 화면). 그래서 화면보다 먼저, 쓰는 곳이 많은 것부터 한다. 이 과도기에 옛 화면
안에 새 버튼이 섞여 보이는 건 정상이다 — 깨지지만 않으면 된다.

**화면 작업에서는 여러 화면이 쓰는 컴포넌트를 고치지 않는다.** 화면 하나는 공용
컴포넌트의 다수결이 아니다. `components/ui/`에 있어도 **그 화면(또는 그 탭)만
import하는 것**은 화면 작업에서 함께 고친다 — import하는 파일을 grep해서 판단한다. 화면에서 본 공용 컴포넌트가 지금 코드와 다르면 인벤토리의 그
컴포넌트 행에 적어 두고, 컴포넌트 작업에서 전 프레임을 모아 정한다. 화면 전용
카드·블록(`features/<탭>/components/`)은 화면 작업에서 고친다.

## 작업 하나(컴포넌트 또는 화면)의 절차

아래 체크리스트를 복사해 진행 상황을 표시한다.

```
- [ ] 1. 인벤토리에서 대상 행과 관련 결정을 확인
- [ ] 2. 쓰는 곳 확인 (컴포넌트면 grep으로 import하는 파일 목록)
- [ ] 3. v4 조회 — get_design_context + 같은 이름 노드 전 프레임 비교
- [ ] 4. RN으로 옮김 (references/rn-translation.md)
- [ ] 5. 에셋: 기존 파일과 먼저 대조
- [ ] 6. tsc / lint / test 통과
- [ ] 7. 에뮬레이터 확인 + 위치 비교 (references/verification.md)
- [ ] 8. 쓰는 다른 화면이 깨지지 않았는지 확인
- [ ] 9. 인벤토리 상태·결정 갱신
```

**3. 조회.** `get_design_context` 전에 `figma-design-to-code` 스킬을 로드한다.
화면 노드 ID는 인벤토리의 "화면" 표에 있다. v4에는 **컴포넌트 인스턴스가 하나도
없다** — 모든 게 낱개 도형이고 레이어 이름만 남아 있다. 그래서 **컴포넌트 작업**은
한 화면의 노드만 보지 말고, 같은 이름의 노드를 전 프레임에서 모아 변형을 비교한다
(`references/figma-queries.md`). 화면 작업은 그 화면의 `get_design_context`로 충분하다.

**4. 옮기기.** 응답은 항상 웹 React + Tailwind다. 변환 규칙과 이미 한 번씩 틀린
함정은 `references/rn-translation.md`. 색은 응답의 `var(--text/body, #…)`에서
**변수 이름**을 읽어 `COLOR`에서 찾는다 — hex를 복사하지 않는다.

**5. 에셋.** 새로 받기 전에 기존 `assets/images/`에 같은 그림이 있는지 본다.
로그인의 DNA는 v4에서 크기만 바뀐 같은 그림이었다. 비교는 scale 4 내보내기와
기존 파일을 같은 크기로 잘라 나란히 놓고 본다. 새로 받아야 하면 AGENTS.md 규칙 7
(알파가 빠진 내보내기)을 따른다.

**7. 확인.** 타입 검사는 확인이 아니다. 에뮬레이터에서 보고, Figma 내보내기와
**요소 위치를 숫자로 비교**한다(`scripts/compare_bands.py`). 모든 요소가 같은 양만큼
어긋나면 정상이고(상태바 차이, 이 기기에서 약 24.8pt), 혼자 다른 요소가 버그다.
**스크린샷은 비교 전에 반드시 열어서 본다** — 에러 화면 두 장도 차이가 0이다.

## 함정 (작업하며 계속 추가)

- **폰트가 바뀌었다.** 본문은 IBM Plex Sans KR(`font-plex`, `font-plex-semibold`,
  `font-plex-bold`). Pretendard는 **Figma 텍스트 노드가 Pretendard라고 할 때만**
  쓴다 — 뒤로가기 칩의 `←`, 행 끝의 `>`, `✓`(Plex에 없는 글자). "로그인 →"처럼 Plex
  문구 안의 `→`는 Plex다. 글자별로 나누지 말고 노드의 폰트를 따른다. 응답의
  `font-['IBM_Plex_Sans_KR:SemiBold']`는 `font-plex-semibold`로 옮긴다.
- **그라디언트 각도는 픽셀 기준이다.** `linear-gradient(166deg, …)`를 `start`/`end`
  0→1로 옮기면 틀린다. `cssGradientPoints(angle, figmaW, figmaH)`를 쓴다.
- **v4 프레임에도 38pt `PhoneHeader` 목업이 있다.** 위치는 프레임 y − 38로 계산한다.
- **줄 상자가 서로 겹치는 배치**(워드마크·인사말·라벨)는 음수 마진 대신 절대 위치로
  둔다. 로그인 화면이 그 예다.
- **`history` 상태가 v4에서 사라졌다.** 지난 기록의 선택된 답도 활성(분홍)과 같은
  색이다. 코드의 `history`는 활성 색 + 눌리지 않음으로 둔다.
- **간격·반경 변수(`LifeDNA 간격·반경`)는 390 단위라 쓰지 않는다.** 노드 값을 읽는다.
- **v4 값에는 소수가 많다**(v3의 정수를 0.564배 한 값). 그대로 쓴다 — 억지로
  반올림하면 프레임마다 다른 값이 된다.
- **가로 `ScrollView`(페이저)를 `flexGrow: 1` 기둥 안에 두면 세로로 늘어난다** — 아래 내용을
  화면 가운데까지 밀어낸다. 페이저에 `flexGrow: 0`.
- **폭 전체를 덮는 절대 위치 `Text`는 그보다 먼저 그린 형제의 탭을 가로챈다**(달력 제목이
  `<`를 막았다). 누를 수 있는 것을 나중에 그리거나 글자에 `pointerEvents="none"`.
- **공용 컴포넌트 값은 한 화면에서 정하지 않는다** — `Button` 글자를 로그인 하나만 보고
  SemiBold 9.6으로 정했다가, 5개 프레임 중 3개가 Bold 11.3이라 고쳤다.
- **`adjustsFontSizeToFit`은 안드로이드에서 글꼴 배율 1.0인데도 이미 들어맞는 글자를
  7~9% 줄일 수 있다.** `maxWidth`와 함께일 때(개선책 근거 문구)와, `left`+`right`로 폭을
  준 6.77pt·줄 9.03의 빠듯한 줄(MY 배너)에서 그랬다. 고정 칸 안 가운데 정렬한 알약·만족도
  라벨은 1.0에서 줄지 않았다. 넣었으면 **반드시 1.0에서 글자 높이를 재 본다.** 줄바꿈될 수
  있는 글자는 절대 위치 대신 일반 흐름에 두는 편이 나았다.
- Python으로 파일을 쓸 때는 `open(..., newline='')` — Windows에서는 말없이 CRLF로 쓴다.
- 긴 Python 분석 스크립트는 bash heredoc보다 Write 도구로 파일을 만들어 실행한다 —
  heredoc 안의 따옴표가 깨지는 일이 있었다.
- **문서 일부는 작업 폴더에서 CRLF 줄바꿈이다**(git에는 LF). 스크립트로 문자열을
  치환할 때 줄바꿈이 든 패턴이 소리 없이 안 맞는다 — 파일의 줄바꿈을 먼저 보고 맞추거나,
  치환 뒤 바뀐 개수를 확인한다. heredoc 안의 Python에 `'\\n'`을 쓰면 파일에 진짜 줄바꿈이
  들어간 적도 있다 — 문서 수정은 Edit 도구가 안전하다.
- 에뮬레이터·Metro 환경 문제(adb 포트, 로그인된 세션, 원래 폴더의 Metro)는
  `references/verification.md`에 정리돼 있다.
