# 백엔드 API 연동 규칙 (lifeDNA)

이 스킬은 **서버를 화면에 붙이는 단계**를 다룬다. UI를 Figma에서 옮기는 작업은 `figma-build-ui` / `figma-implement-component`를 본다.

## 프로젝트 컨텍스트

- 서버: `https://antiaging-dna.anzaanza.cloud`, 스펙 `GET /v3/api-docs`
- 운영 환경 하나뿐이다. **개발·스테이징이 없다** — 검증도 운영 서버에서 한다
- 테스트 계정: `fetest01` / `Test1234!`

**코드에서 진실은 여기 있다** (문서가 아니라):

| 무엇 | 파일 |
|---|---|
| fetch 래퍼, `ApiError`, `messageFor` | `src/lib/api.ts` |
| 세션·JWT·`Stack.Protected` | `src/lib/auth.tsx` |
| 점수 타입·등급·캘린더 색·경로 빌더 | `src/lib/score.ts` |
| 일지 한국어 라벨 ↔ enum (양방향) | `src/lib/diary-request.ts` |
| 회원가입 라벨 ↔ enum | `src/lib/sign-up-request.ts` |
| 인증된 GET 훅 (포커스 시 재조회) | `src/lib/use-api-query.ts` |
| 로컬 달력 날짜 헬퍼 | `src/lib/dates.ts` |

`docs/backend-api.md`와 `docs/backend-backlog.md`는 **캐시다.** 의존하기 전에 서버에서 확인한다.

## 절대 어기면 안 되는 서버 계약

전부 실제로 버그를 낸 항목이다. 스타일 취향이 아니다.

1. **`GET /api/scores/{date}` · `/today`를 부르지 않는다.** 조회만 해도 그 날짜의 점수 행이 서버에 **영구히 생긴다**(`DELETE` → 405). 캘린더가 한 달을 그리면 그 달이 통째로 기록으로 남는다. 구간 조회(`?from&to`)는 행을 만들지 않으니, 하루치가 필요해도 **하루짜리 구간**을 쓴다. `score.ts`의 `scoresPath()`가 구간만 만드는 이유다. (백로그 31)
2. **응답의 `grade`를 쓰지 않는다.** 누적·평활된 `displayTotal`을 따라가서 그날과 어긋난다 — `dailyTotal 16.32`인 날이 `GOOD`, `94.73`인 날이 `WARN`으로 나온 실제 사례가 있다. 날짜별 등급은 `dailyTotal`에 70/40 경계를 직접 적용한다(`gradeFor`). (백로그 32)
3. **`dailyTotal === null`이 "그날 기록 없음"의 유일한 판정이다.** 일지가 없는 날도 점수 응답은 200이고 `displayTotal`·`grade`가 채워져 온다. 구간 응답에 날짜가 **있다고 해서 일지가 있는 건 아니다**(1번 때문에 생긴 행이 섞인다).
4. **`PUT /api/diaries/{date}`는 병합이 아니라 전체 덮어쓰기다.** 부분 저장하면 나머지가 전부 `null`이 된다. 일지를 쓰는 화면은 **열릴 때 그날 값을 불러와 채운 뒤** 저장해야 하고, 그 로드가 끝나기 전엔 저장 버튼을 막는다. (백로그 30)
5. **날짜는 기기 로컬에서 만든다.** `toISOString()`은 UTC라 KST에서 09:00까지 전날을 가리킨다 — 아침 일지가 전부 어제로 기록된다. `dates.ts`의 `isoDate()`를 쓴다.
6. **`stressLevel: 0`은 아직 400이다.** 슬라이더 0은 생략한다. (백로그 7 — "허용 배포 완료" 회신이 왔지만 서버에 반영돼 있지 않다)

## 작업 절차

1. **백로그에서 🟡 프론트를 먼저 본다.** `docs/backend-backlog.md`는 *다음에 누가 움직여야 하나*로 정렬돼 있고, 🟡는 "백엔드가 답했고 **우리가 화면을 고쳐야 함**"이다. 가장 놓치기 쉬운 상태다.
2. **서버에서 계약을 검증한다** (아래 절차). 회신 문서만 보고 코드를 고치지 않는다.
3. **매핑은 `src/lib/`에, 화면은 라벨만 본다.** 화면은 enum 상수를 몰라야 하고, 매핑 파일은 컴포넌트를 몰라야 한다. 미응답 필드는 **생략**하고, 표에 없는 라벨은 던진다(조용히 버리면 Figma가 선택지 이름을 바꾼 걸 놓친다).
4. **조회는 `useApiQuery`를 쓴다.** 마운트가 아니라 **포커스**에 재조회한다 — 화면들이 push 밑에 살아 있어서, 저장하고 돌아오면 저장 전 숫자가 보인다.
5. **없는 값을 지어내지 않는다.** 서버에 값이 없으면 `—`, 서버가 만들어야 할 문장이면 빈 문자열로 둔다. 근거 없는 환산 계수·경계값을 만드는 건 이 프로젝트가 계속 거절해 온 것이다(백로그 22·26 참고).
6. 에뮬레이터에서 확인한다 (아래).
7. `docs/backend-api.md`·`docs/backend-backlog.md`·`AGENTS.md`를 갱신한다 (아래).

## 서버 계약 검증 절차

**"배포 완료"를 믿지 않는다.** 이 프로젝트에서 두 번 틀렸다 — 17번 시드 계정 `demo`는 계정 자체가 없었고, 5차 회신의 `stressLevel: 0` 허용과 `orbState` 필드는 서버·스펙 어디에도 없었다. 그대로 믿고 고쳤으면 일지 저장이 400으로 깨졌다.

1. **응답과 스펙을 둘 다 본다.** 실제 호출 결과와 `GET /v3/api-docs`를 함께 확인한다. 하나만 보면 놓친다.
2. **`curl` 말고 python `urllib`로 친다.** 이 셸(Git Bash on Windows)에서 curl은 중첩 따옴표 때문에 JSON 본문을 망가뜨린다 — "Failed to read request" 400을 실제로 먹었다. 스크래치패드에 작은 스크립트를 쓰고 돌린다.
3. **검증 중에도 단일 날짜 점수 조회를 부르지 않는다.** 확인하겠다고 부르면 그 계정 통계를 영구히 오염시킨다(계약 1번).
4. **과거 데이터가 필요하면 직접 심는다.** `PUT /api/diaries/{date}`가 과거 날짜를 그대로 받는다. 지난 기록·주간 그래프·캘린더처럼 히스토리가 있어야 보이는 화면은 시드 없이는 확인이 불가능하다. 등급 경계를 양쪽 다 넘도록 좋은 날·나쁜 날을 섞고, 며칠은 일부러 비워 "기록 없음"도 보이게 한다.
5. **덮어쓰기 계약을 존중한다.** 검증하느라 `PUT`을 날렸으면 원래 값으로 되돌려 놓는다.
6. 회신이 틀렸으면 **근거와 함께** 백로그에 되돌려 적는다 — 상태를 🔴로 내리고, 재현한 요청/응답을 그대로 붙인다.

## 에뮬레이터 확인

기동·스크린샷·딥링크·좌표 스케일 절차는 `figma-build-ui`의 "실기기 검증"을 그대로 쓴다. 연동 작업에만 해당하는 것:

- **타입체크는 검증이 아니다.** 붙인 값이 화면에 맞게 나오는지 눈으로 본다.
- **시드 데이터를 넣은 뒤에 본다.** 빈 계정에서는 붙였는지 안 붙였는지 구분되지 않는다.
- **숫자를 서버 응답과 대조한다.** "그럴듯한 숫자가 보인다"가 아니라, 구간 조회 결과와 화면의 값이 일치하는지 확인한다.
- 저장하는 화면은 **저장 → 나갔다 → 다시 들어오기**까지 해본다. 4번(덮어쓰기)과 4단계(포커스 재조회)가 여기서 드러난다.
