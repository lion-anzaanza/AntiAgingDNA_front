# 프론트 연동 현황

**우리가** 움직여야 하는 것을 모은 문서입니다. 백엔드에게 넘기는 요청은
[backend-backlog.md](backend-backlog.md), API가 무엇을 하는지는
[backend-api.md](backend-api.md)에 있습니다. 이 문서는 백엔드에게 주지 않습니다.

- 마지막 전수 점검: **2026-09-30** — 항목마다 문서가 아니라 코드와 서버 응답을
  대조했습니다.
- 번호는 백로그와 **같은 번호 체계**를 씁니다. 백엔드가 답한 항목이 우리 차례가
  되면 번호 그대로 이쪽으로 옮기고, 새로 여는 항목은 두 문서를 통틀어 다음
  번호를 받습니다 (다음 번호: **38**).

두 가지 상태만 있습니다.

| 상태 | 뜻 |
|---|---|
| 🟡 프론트 | 막힌 것 없음 — 우리가 붙이면 됩니다 |
| 🟣 기획 | 기획·디자인이 정해야 우리도 백엔드도 움직일 수 있습니다 |

**🟡는 이 문서에서 가장 놓치기 쉬운 상태입니다.** "백엔드가 답했다"와 "할 일이
없다"는 다릅니다 — 답이 화면 변경을 요구하면 그 일은 여기에 🟡로 남아야 하고,
백로그에서 닫으면서 이쪽에 옮기지 않으면 그 작업이 사라집니다. 네 건이 실제로
그렇게 묻혀 있다가 다시 읽으면서 드러났습니다.

## 🟡 프론트 — 지금 붙일 수 있는 것

### 36. 홈 스트레스 `%`가 음수로 나올 수 있습니다 (버그)

`home-screen.tsx`가 `(x − 1) / 9 × 100`을 씁니다. 1~10이던 시절의 공식인데,
7번으로 서버가 0을 받기 시작해서 **스트레스 0을 기록한 날은 `−11%`로
표시됩니다.** 방향(높을수록 스트레스가 많음, backlog 26)은 그대로 두고 도메인만
0~10으로 맞추면 됩니다.

### 37. 가입 검증에 비밀번호 규칙이 없습니다

스펙에 규칙이 생겼습니다 — 8~72자, 영문과 숫자를 각각 하나 이상
(`^(?=.*[A-Za-z])(?=.*\d).+$`). `sign-up-form.tsx`는 아직 "서버가 비밀번호
규칙을 문서화하지 않았다"며 빈 값만 거릅니다. 같은 파일의 아이디 규칙 주석도
"잠정"이라고 적혀 있는데, 이제 스펙에 박혀 있습니다.

지금은 규칙을 어긴 비밀번호가 STEP 3까지 통과한 뒤 서버에서 400으로 돌아옵니다.
실패를 **설명할** 자리는 여전히 없으므로(에러 디자인 없음) 다른 칸처럼 다음
버튼을 막는 방식이 됩니다.

### 12. 날씨 자동 기록

서버는 준비돼 있습니다 — `PUT`에 `lat`/`lon`/`weatherLocationLabel`을 보내면
저장 시점에 한 번 조회해서 기록합니다 (`backend-api.md` Weather). 앱은 좌표를
보내지 않고, 오늘의 기록·상세보기의 날씨 카드는 Figma 값이 그대로입니다.

붙이려면: 위치 권한 요청, `weatherCondition` 10종 → 아이콘·문구 매핑, 위치
표기 문구(`서울`)를 어디서 얻을지. 마지막 것은 서버가 만들지 않습니다.

### 33. 홈 5개 영역 밸런스

신체·정신·감정·사회 네 영역은 서버가 값과 등급을 줍니다. 그런데 **다섯 칸이
전부 Figma 값으로 고정**돼 있습니다. 신체·정신·사회는 지금 붙일 수 있습니다.
감정은 그날 `stressLevel`이 없으면 `null`이고, 환경은 항상 `null`이라 둘 다
아래 🟣(빈 영역 디자인)에 걸려 있습니다.

### 32. 날짜별 등급을 `dailyGrade`로 교체 (선택)

서버에 `dailyGrade`가 배포됐습니다. 지금 코드가 `dailyTotal`에 70/40을 직접
적용하는 것과 **같은 값**이라(2026-09-30 `demo` 계정으로 확인) 급하지 않습니다.
바꾸면 경계값을 프론트에 복제하지 않아도 됩니다.

### 11. 홈 나의 LifeDNA 정보 — 신체 탭

v4가 신체 탭을 **수면 시간 · 수분 섭취량** 두 장으로 그립니다. 막대 7일 · 진행
바 · 좋음/주의/위험은 `GET /api/scores/items?from&to`로 지금 붙일 수 있습니다.
코멘트 문장은 27번(🟣), 수면 값은 29번 때문에 비어 있을 수 있으니 `demo` 계정과
새 계정 둘 다로 확인합니다. 나머지 네 탭은 아래 🟣 11번.

### 10. 홈 지표 카드 뱃지 — 수분 부분

`/api/scores/items`가 `waterGrade`(70/40)를 줍니다. 다만 화면의 뱃지는
`좋아요`/`조금 부족`/`높음`이라 GOOD/WARN/DANGER와 어떻게 대응시킬지 정해야
합니다. 수면 뱃지는 `sleepGrade`가 항상 `null`이라 29번이 풀려야 하고, 스트레스
뱃지는 서버에 등급이 없어 백로그 10번으로 남아 있습니다.

## 🟣 기획·디자인 — 결정 대기

### 27·25. 문장과 문구 규칙

**서버는 문장을 만들지 않습니다** — 원자값만 주고 문장은 프론트가 조합하는
것으로 확정됐습니다(backlog 27). 그런데 "어떤 값일 때 어떤 문장"인지의 규칙이
없어서 아래 자리가 전부 비어 있습니다. 규칙을 지어내지 않는 것은 22·26번에서
양쪽이 합의한 원칙입니다.

| 자리 | 예시 (Figma) |
|---|---|
| 홈 오브 카드 상태 칩 | `안정적으로 성장 중` |
| 홈 오브 카드 설명 2줄 | `컨디션이 좋아 오브가 푸른빛이에요 / 나빠지면…` |
| 홈 나의 LifeDNA 정보 카드 코멘트 | `올빼미형 - 취침이 3일째 30분씩 빨라졌어요.` |
| 일지/메인 그래프 요약 | `어제보다 수면 +40분 · 스트레스 −1` |
| 캘린더 일간 요약 코멘트 | `전반적으로 안정적입니다. 스트레스 관리가…` |
| 주간 리포트 · 개선책 인사이트 | `수면 7시간 → 컨디션 +6점` |

규칙이 나오면 필요한 원자값을 백엔드에 요청합니다 — 백엔드는 "지표를
알려주면 11번처럼 추가하겠다"고 했습니다.

### 11. 나의 LifeDNA 정보 — 나머지 네 영역

v4 개편(2026-09-30)이 신체 탭을 **수면 시간 · 수분 섭취량 두 장**으로
되돌렸습니다 — `/api/scores/items`가 맞춰 나온 구성 그대로라 신체 탭은 위 🟡
11번으로 붙일 수 있습니다. 남은 것은 정신·환경·감정·사회 탭입니다. v4가 그리지
않았고 원자값도 없습니다(27 · 33). 각 탭에 어떤 지표를 둘지 기획이 정해야
합니다.

### 24. 마이페이지 유형 라벨

`올빼미 - 고민감 - 누적형`. `/api/dna`에 원자값(수면유형·민감도 3종·생활리듬…)은
있지만 어떤 값을 어떤 순서·기준으로 이어 붙이는지, "누적형" 같은 표현의 기준이
없습니다.

### 29. 취침·기상 시각을 입력받을 방법

`InputTime_Card`는 표시 전용이고 피커가 디자인에 없습니다. 그래서 `sleepMinutes`가
항상 `null`이고, 홈 수면 카드·일간 요약 수면·상세보기 시각이 전부 `—`입니다.
네이티브 피커, 직접 입력, 구간 알약(이건 API 변경 필요) 중 하나를 디자인이
정해야 합니다.

### 30. 이미 기록한 날 다시 들어가면 '수정'이 됩니다

`PUT`이 전체 교체라 오늘의 기록은 그날의 답을 불러와 채운 채 열립니다. Figma에는
"이미 쓴 날을 고치는" 화면이 없습니다 — 재진입 시 안내 문구를 바꿀지, 저장된 답을
`history`로 보여주고 "수정하기"를 따로 둘지 정해야 합니다.

### 33. 값이 없는 영역을 어떻게 그리나

`environment`는 입력원이 없어 **계속 `null`입니다**(백엔드 A-1). `emotion`도 그날
스트레스를 답하지 않으면 `null`입니다. Figma의 5개 영역은 항상 좋음/주의/위험 중
하나로 그려져 있고 빈 상태가 없습니다.

### 32. 기록이 하나도 없는 사용자에게 오브가 점수를 말해도 되나

일지를 한 번도 안 쓴 계정도 `displayTotal`이 가입 진단 기반 값(예: 83점)으로
나오고, 홈 오브 카드는 그 숫자를 그립니다. "진단 기반 출발점"이라는 뜻이라면 그렇게
읽히는 문구가 필요합니다 — 25·27번 문구 규칙과 같이 정하면 됩니다.

### Figma가 코드보다 뒤처진 곳

백엔드 결정에 맞춰 화면은 이미 고쳤지만 디자인 파일은 그대로인 곳입니다.
디자이너에게 전달할 것들입니다.

- 회원가입 STEP 1 — 성별·직업·년/월/일이 빠지고 아이디·출생연도가 들어갔습니다 (13, 18)
- 운동 종류 네 번째 칸 `근력+유산소` (8)
- 걷기 시간 `30분~1시간` · `1~2시간` (9)
- 민감도 3종 — 0~10 슬라이더가 아니라 4지선다 (6)
- 홈 수분 카드 — `1.6L`가 아니라 `3~5잔` (26)
- 약관 동의 — 마케팅 정보 수신은 `[필수]`가 아니라 `[선택]` (1)
- 회원탈퇴 — 확인 화면이 없어 플랫폼 기본 다이얼로그를 씁니다 (24)

## 화면별 커버리지

화면에 그려진 것 하나하나가 **서버에서 오는지(API)**와 **우리가 붙였는지(화면)**를
따로 봅니다. 두 열을 나눈 이유: 한 열이던 시절 `API ✅ / 화면 ❌`인 줄 여섯 개가
전부 초록으로 보여서 아무도 남은 일로 세지 않았습니다. **`API ✅ / 화면 ❌`인
줄이 위 🟡 목록입니다.**

| 화면 | 그리는 것 | API | 화면 |
|---|---|---|---|
| 로그인 · 회원가입 | 인증 · 중복확인 · 회원탈퇴 | ✅ | ✅ |
| | 비밀번호 규칙 검증 | ✅ | ❌ 37 |
| | 아이디 · 비밀번호 찾기 | ❌ 백로그 14 | ❌ |

| | 상태 칩 · 설명 2줄 | ✅ 원자값 | ❌ 🟣 27 |
| 홈 · 지표 카드 | 수분 `3~5잔` | ✅ | ✅ |
